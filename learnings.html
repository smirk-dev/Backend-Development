4. Mistakes and traps that cost time

TrapCauseFix
One script silently stopped working with "Identifier '$' has already been declared" Two classic scripts on one page each declared const $ at top level. Classic scripts share one global scope for const and let, so the second file failed to load at all. Load them as type="module"; each module has its own scope. Otherwise wrap the code in a function or block.
Modules do not run when the file is double-clicked Browsers block module loading from file:// addresses. Serve the folder over HTTP, for example py -3 -m http.server 8000.
Checks returned "undefined" for every panel The test server was started in the wrong folder and answered 404. Check the status code with curl before debugging the page.
XSS through innerHTML innerHTML turns a string into real elements, and an element such as an image with an onerror attribute can run script. Use textContent for untrusted text. The demo shows the same string as inert text in one box and as a real element in the other (without a live script).
Handlers not firing for new elements Listeners attached directly to elements only cover elements that existed at that moment. Use event delegation on a parent.

5. How it was checked

The page was opened in headless Chrome and driven through the DevTools protocol. Every button was clicked, every output panel was read back and compared with the expected result, and the console was watched for errors. The To-Do app was tested for adding by button and by the Enter key, toggling and deleting.

6. Rules of thumb

  • Use const by default, let when you must reassign, and avoid var.
  • Use addEventListener, not inline handlers.
  • Use classList for styling changes.
  • Use textContent for text; use innerHTML only for markup you wrote yourself.
  • Delegate events to a parent when items are created and removed dynamically.
  • When something silently does nothing, look at the browser console first.
